## Objective
Implement defense-in-depth database security for VaultRAG:
1. Enforce PostgreSQL `FORCE ROW LEVEL SECURITY` on `documents_document` and `documents_chunk` so cross-tenant rows are blocked at the database engine level even if application filters were bypassed.
2. Build an append-only `AuditLog` service with database privileges revoked for `UPDATE` and `DELETE` on `audit_auditlog`.
3. Implement request-scoped database connection middleware executing `set_config('app.tenant_id', <tenant_id>, true)` per transaction.
4. Expose tenant-scoped Audit Log query API and build an interactive Audit Log Viewer page in the frontend.

---

## Tasks

### Task 1: Create `audit` Django App & Append-Only `AuditLog` Model
- Create Django app `backend/audit` and register in `INSTALLED_APPS`.
- Define `AuditLog` model with fields:
  - `id` (UUIDField, primary_key)
  - `tenant_id` (UUIDField, db_index=True)
  - `user_id` (UUIDField, null=True, blank=True, db_index=True)
  - `user_email` (CharField, max_length=255)
  - `action` (CharField with choices: `query`, `ingest`, `delete_document`, `grant_permission`, `revoke_permission`, `login`)
  - `query_text_sanitized` (TextField, blank=True)
  - `retrieved_chunk_ids` (JSONField, default=list)
  - `denied_chunk_count` (IntegerField, default=0)
  - `ip_address` (GenericIPAddressField, null=True, blank=True)
  - `latency_ms` (FloatField, null=True)
  - `created_at` (DateTimeField, auto_now_add=True, db_index=True)
- Prevent application-level updates by overriding `save()` and raising `PermissionError` on existing records.
- Create migration and apply database privilege revocation:
  `REVOKE UPDATE, DELETE ON audit_auditlog FROM vaultrag_app;`

### Task 2: Database Connection Middleware (`TenantContextMiddleware`)
- Create `accounts/middleware.py`:
  - Intercept authenticated requests with verified `UserContext`.
  - Inside database connection cursor, execute:
    `SELECT set_config('app.tenant_id', %s, true);`
  - Ensure transaction isolation (`is_local = true`) so pooled connections never leak context between requests.

### Task 3: PostgreSQL `FORCE ROW LEVEL SECURITY` Migrations
- Create raw-SQL migration in `documents` applying:
  - `ALTER TABLE documents_document ENABLE ROW LEVEL SECURITY;`
  - `ALTER TABLE documents_document FORCE ROW LEVEL SECURITY;`
  - `ALTER TABLE documents_chunk ENABLE ROW LEVEL SECURITY;`
  - `ALTER TABLE documents_chunk FORCE ROW LEVEL SECURITY;`
  - Define tenant isolation policies:
    ```sql
    CREATE POLICY tenant_isolation_policy ON documents_document
    FOR ALL
    USING (tenant_id::text = current_setting('app.tenant_id', true))
    WITH CHECK (tenant_id::text = current_setting('app.tenant_id', true));

    CREATE POLICY tenant_isolation_policy ON documents_chunk
    FOR ALL
    USING (tenant_id::text = current_setting('app.tenant_id', true))
    WITH CHECK (tenant_id::text = current_setting('app.tenant_id', true));
    ```

### Task 4: Wire Audit Service into Chat & Document Endpoints
- Record audit log entries on:
  - Chat queries in `ChatService` (capturing query text, retrieved chunk UUIDs, response latency).
  - Document uploads and deletions in `documents/views.py`.
  - Permission grant and revocation in `permissions/views.py`.

### Task 5: Audit Log API & Frontend Viewer
- Backend: `GET /api/v1/audit/logs/` (tenant-scoped, paginated, filterable by user, action, and date range).
- Next.js: Create `/audit` page with searchable audit log table, event badges, and latency metrics.

## Verification & Acceptance Criteria
1. **RLS Enforcement Test:** Querying `documents_chunk` or `documents_document` without setting `app.tenant_id` returns **0 rows**.
2. **Audit Immutability Test:** Attempting to `UPDATE` or `DELETE` rows in `audit_auditlog` raises a database permission error.
3. **Cross-Tenant Test:** A user from Tenant A cannot see Tenant B audit logs or documents under any circumstance.
4. **All unit tests pass:** `python manage.py test audit documents chat --keepdb`.
